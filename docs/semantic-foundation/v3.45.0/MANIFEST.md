## Semantic changes
Owner decision (2026-11-21): the Manus host is admitted as a named consumer of the domain projection architecture. It has exactly one canonical surface, `manus-cloud`; the shell a Manus session runs commands in is not a separately registered interaction surface, so no `manus-cli` coordinate is created.
- `semantics/domain_consumer_bindings.yaml` (`l9.domain-consumer-binding-catalog/global@1`):
  - New `l9.domain-consumer-binding/manus@1`: `consumer.kind: host`, `consumer.identity: manus`, `actor_ref: l9.actor-registry/global@1#manus`, `surface_refs: [l9.surface-registry/global@1#manus-cloud]`. No `successor_of`; this is the first binding for this consumer, not a successor to a Manus predecessor.
  - `requires`: `l9.projection/governance@1`, `l9.projection/identity-attribution@1`, `l9.projection/capabilities-dependencies@1`, `l9.projection/contracts-conformance@1`, `l9.projection/evidence-provenance@1`.
  - `conditional`: `l9.projection/architecture@1` under `hosted_skill_requirement`; `l9.projection/strategic-value@1` and `l9.projection/signals@1` under `explicit_task_requirement`.
  - `authority.binding_grants_permissions: false`; `authority.action_authority: externally_resolved`; `unresolved: []`; `predecessor_profiles: []`.
  - Catalog `purpose`: "each of six named consumers" -> "each of seven named consumers". Count correction only; no global rule, consumer kind, activation condition, unresolved block, composition contract or validation rule changes.
- `scripts/validate-semantics.py`: `DOMAIN_BINDING_IDS` gains `manus`, and the RC-034 census message and its header comment move from six to seven v1 bindings. Validation tooling, not admitted meaning (ADR-041's classification).
No invariant, contract, vocabulary term, source class, projection profile, composition profile or payload schema changes. No derivation coordinate changes. `domain_consumer_bindings.yaml` is selected by no projection profile, so no projected bytes change.
