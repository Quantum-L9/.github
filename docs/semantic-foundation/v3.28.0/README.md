# Semantic Foundation v3.28.0

Status: **ADMITTED ADDITIVE SUCCESSOR** (ADR-025, 2026-11-08).

v3.28.0 admits ten paired projection and composition profiles. Twenty registered payload schemas come with them: one projection schema and one composition schema per pair. Each profile pair selects existing canonical sources for one consumer view. Each payload schema states what a conforming selected payload looks like, so the compiler's `payload_schema` criterion resolves instead of staying `unresolved`.

The repository owner admitted this release in ADR-025, which records the decision, its scope and the limitations accepted as its basis. Admission takes effect at the `main` commit that merges Quantum-L9/.github#211.

## Bounded delta

- `semantics/projection_profiles.yaml` and `semantics/composition_profiles.yaml` gain ten profile pairs:
  - `authority-resolution`, `evidence-assessment`, `semantic-change-context`, `architecture-break-test`, `globalization-assessment`;
  - `work-state-continuity`, `hard-constraint-context`, `identity-assurance`, `strategic-metacognition`, `strategic-planning-context`.

  Each composition places every source under its source-class namespace (`placement: source_class_namespace`).
- Three profiles select seven sources field by field instead of whole (`$`): `identity-assurance`, `strategic-metacognition` and `strategic-planning-context`. Only each source's own `schema` field is left out. See "Explicit field selection".
- 20 payload schemas are registered under `requires.artifact_schemas`:
  - the `authority-resolution` pair is hand-authored (#211);
  - the other 18 were originally generated by `l9-semantic-compiler schema-derive` (#214).

  All 20 were later patched in place (`RELEASE_VALIDATION.md`, "Schema patch ledger").
- No ledger, rule, contract or invariant changes. ADR-025 records the admission decision.

## Schema origin and in-place patches

The 18 derived schemas were written by `schema-derive` (Quantum-L9/l9-semantic-compiler-engine PR #26) from the payloads each profile selects. Each records its derivation in a `derivation` block: method `l9.schema-derivation/selected-payload@1`, the authority revision, and the profile, selector-model and source digests. Twelve were derived at `290bcd90` and six at `2349a90b`. Their recorded digests still equal the producer's pins at the qualified coordinates.

After registration, the 20 schemas were patched in place. None was regenerated or replaced:

- **381 `min_items` declarations under `type: string_list` were removed.** That is 18 in the hand-authored pair and 363 in the derived schemas. The pinned v1 interpreter reads `min_items` only for `type: array`, so none of them was enforced. Removing them changes no validation outcome; it only stops the schemas from claiming enforcement that does not happen.
- No other byte changed. The registered schemas therefore differ from `schema-derive` output by exactly those keys.

## What a retained constraint means

The schema patch ledger in `RELEASE_VALIDATION.md` classifies every retained `required`, `const`, `enum` and array `min_items` constraint:

- **Governing (361):** follows from a canonical declaration: the profile's output schema, the composition's source classes, an explicit selector, or the exact id-filter selector set.
- **Pinned snapshot (3,970):** describes the selected data at the recorded source revision. It is accurate at the qualified coordinates but is **revision-bound, not semantic law**. A later change to a selected source can fail `payload_schema` until the schema is edited. For example, a new actor or surface fails `identity-assurance`, and a new architecture rule fails `architecture-break-test`.
- **Unsupported (0):** none remain.

Selector equivalence, provenance, digest validation and composition coverage are separate producer checks. The payload schemas add no authority and do not prove exact membership.

## Explicit field selection

The compiler finds a payload schema by `properties.schema.const` and checks that constraint against the payload's own `schema` field. A whole-document selection carries the source's own `schema` field (`l9.actor-registry/v1`, `l9.surface-registry/v1` or `l9.schema-definition/v1`), so no v1 projection schema could be satisfied.

Seven `$` selectors were therefore replaced by one selector per top-level field, in source order:

- `actor_registry` and `surface_registry` (`identity-assurance`);
- `strategic_plan_metacognitive_analysis_schema` (`strategic-metacognition`);
- `strategic_plan_graph_schema`, `affected_strategic_closure_schema`, `strategic_planning_episode_schema` and `strategic_plan_revision_candidate_schema` (`strategic-planning-context`).

Every other field is still selected. Source identity, revision and digest stay bound to each artifact and receipt, and each source's `artifact_id` stays selected.

Consumers no longer receive the source document's kind and version marker. For the five schema-definition sources, that marker is the schema dialect identifier. The declared consumers have no implementation reachable from this release, so whether any of them materially needs the field is **Unknown**. The change is not claimed to be lossless. The owner accepted the narrowing as the intended v1 selection contract (ADR-025). The per-source ledger is in `RELEASE_VALIDATION.md`.

## What admission covers and what it does not

| Class | Status |
|---|---|
| **Admitted semantic definitions** | The ten `l9.projection/<name>@1` and ten `l9.compose/<name>@1` profiles, and the twenty registered payload schemas. |
| **Revision-bound schema restrictions** | The 3,970 pinned-snapshot constraints. They are accurate at the qualified coordinates and are not semantic law. |
| **Verified producer behavior** | All ten pairs pass `project`, `compose`, independent re-verification and receipt validation with the pinned compiler. All 461 targeted negative cases are rejected as intended, and an independent replay is byte-identical (`RELEASE_VALIDATION.md`). |
| **Unverified independent consumer behavior** | No independent consumer replay exists for any of the ten profiles. No consumer migration, compatibility or deployment is claimed. |

## Owner decisions (ADR-025)

1. The seven-field narrowing of the three field-selecting profiles is **accepted** as the intended v1 selection contract.
2. The removal of all 381 unenforced `string_list` `min_items`, including the 18 hand-authored `min_items: 1` of the `authority-resolution` pair, is **accepted**. No list-cardinality guarantee is claimed.
3. The 3,970 pinned-snapshot constraints are **accepted** as revision-bound restrictions. A change to a selected source may require a schema update and requalification.
4. Independent consumer replay **remains unestablished**.

The open findings recorded by v3.27.0 remain open.

## Authority

`Quantum-L9/.github` owns the ledgers and these schemas. A derived schema was evidence for the candidate; ADR-025's admission of this release is what gives the registered schemas standing. Admission grants no producer or consumer any mutation, publication, merge, deployment or execution authority, and does not establish downstream adoption or compatibility.
