# ADR-021 — PR-Audit Projection, Source-Namespaced Composition, Payload Schemas, and Validator Closure

**Status:** Candidate for semantic-foundation v3.24.0. Drafted on 2026-10-21 at the repository owner's instruction to give a revision-bound pull-request audit consumer the same mechanical closure the architecture-intelligence (ADR-019) and coding-agent execution (ADR-020) projections received. Admission of v3.24.0 is the acceptance gate; this record does not admit itself.

## Context

A pull-request audit judges a candidate change against governing law. Until now the global part of that law (invariants, contracts, admission and escalation rules, conformance and receipt semantics) reached an audit only by model recall or by reading files at an unpinned revision. The two existing consumer projections already proved the alternative: a profile the owner admits, a compiler that projects it at an exact revision, a receipt the consumer verifies, and a bundle the consumer binds before it cites anything. An audit that cites `L9-EVIDENCE-001` or `l9.contract/validation-and-correctness@1#forbidden` must be able to prove those bytes at the revision it audited against, exactly as it proves the PR head it audited.

Three properties decide what such a profile may select. A category in `forbidden` is evaluated only through a criterion the catalog declares (PROJECTION-016), and the producer evaluates `payload_excludes` against the canonical source, so a selection that overlaps an excluded selector fails closed even when the payload does not carry the excluded record. The engine evaluates exactly `id, class, consumer, purpose, sources, output, successor_of` and reports any `rules` key or any `output` key other than `schema` as unresolved, which turns the receipt `unknown`. And the canonical schema dialect enforces `type, const, enum, required, properties, items, min_items` and nothing else, so a schema keyword outside that set is a promise the receipt cannot prove.

## Decisions

1. **Profile.** `l9.projection/pr-audit@1` is a `consumer` profile for `l9-pr-audit`. It selects, by exact id or by whole canonical section, from thirteen registered ledgers: twenty-four global invariants, sixteen global contracts closed over their `source_invariants`, seven `authority_model` sections, the artifact model's authority classes and derivation rules, one architecture rule, six architecture patterns, the capability state dimensions and their rules, the conformance model's global rules and requirement shape, the receipt kernel with the validation and admission families, the lifecycle rules, state semantics and published-artifact lifecycle, the invalidation rules, the validation result domain, and twenty-seven vocabulary terms. Its `forbidden` list is exactly the five categories ADR-020 gave criteria; no category is added and every excluded path is absent from the selectors. It declares no `rules` and its `output` is only `schema`. Its `purpose` names no skill, command, host, or adapter.

2. **Composition.** `l9.compose/pr-audit@1` composes the profile under `source_class_namespace` placement with exact source coverage, so the consumer binds one composition digest and cites each fact under its source class. Sections that share a name across ledgers (`global_rules`, `authority_classes`) keep their own source identity and their own constraints in the composed view.

3. **Payload schemas.** `semantics/pr_audit_projection.schema.yaml` (`l9.schema/pr-audit-projection@1`) defines `l9.projection.pr-audit/v1`; `semantics/pr_audit_composition.schema.yaml` (`l9.schema/pr-audit-composition@1`) defines `l9.composed-projection.pr-audit/v1` with exactly one namespace per declared source class in declaration order. Both are registered under `requires.artifact_schemas`. Beyond the identity fields each source declares, the schemas pin the properties the consumer relies on: invariant and contract records are `scope: global` and owned by `Quantum-L9/.github`; a contract carries `source_invariants`, `requires`, `guarantees`, `forbidden`, and `outcomes`; `escalation_rules` are `block`, `block`, `remain_unknown`, `require_new_decision`; evidence classes and the receipt kernel grant no authority; invalidation rules keep history immutable and forbid silent consumption of stale input. Every keyword used is one the dialect enforces.

4. **Validator closure.** RC-031 pins the profile, the composition profile, and both schemas whole by canonical-JSON digest; requires exact-id selectors over global records for record collections and existing sections for section selectors; requires the selected contracts to close over their `source_invariants`; requires every forbidden category to have a declared criterion and no selector to overlap an exclusion for its own source class; requires the composed schema to name exactly one namespace per declared source class with exactly the sections its selectors produce; and proves each of these with negative cases that fail closed at the intended field.

5. **Consumer binding.** The consumer verifies the committed bundle with the one shared consumer verifier and binds it only when it is admitted and current, recording provenance before any citation and falling back to no other input, as ADR-019 established for architecture intelligence. The consumer never produces the projection. This record grants the consumer no mutation, publication, merge, admission, or execution authority.

## Review findings (recorded, not resolved)

- `obligation_not_admitted_in_a_selected_source` through `source_authority` carries the limitation ADR-019 and ADR-020 recorded: it restates a property the canonical loader already enforces.
- The projection schema types `global_rules` as a bare object because one artifact carries one source and three selected ledgers declare a section of that name; the composed schema pins each one's keys and values under its namespace. Selection equivalence, not the projection schema, proves the per-source key set.
- `INV-VALIDATION-MONOTONICITY` is scoped `semantic_foundation_release` and is excluded both by the reused criterion and by the schema's `scope: global` pin.
- Downstream consumers cite an "ADR-021" for projection-bundle and binding conventions that was never written in this repository. This record takes the next sequential number; those citations are downstream defects to correct against the records that do exist.

## Consequences

The producer can receipt every source and the composition `pass`, so an audit binds global law at an exact revision and a finding's `authority_id` resolves to projected bytes. A change to any selected record, section, or excluded path is a material change under PROJECTION-007 and PROJECTION-008 and re-opens the receipt; a change to the profile, the composition, or either schema is a new version under RC-031.
