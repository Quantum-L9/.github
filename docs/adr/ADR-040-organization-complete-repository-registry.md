## Context

`semantics/repository_registry.yaml` has been curated membership since v3.15.0: a repository is a member because an entry names it, and `organization_hosting_does_not_imply_l9_membership` allowed a repository hosted in the Quantum-L9 organization to stay out. On 2026-11-17 the organization hosted 61 repositories and the registry listed 34 (33 pinned plus the factory-born `l9-state`). The 27 others had no class, so the one admitted derived view, `l9.repository-view/memory-namespace-l9@1`, gave them no memory membership, and agents working in them could not write to memory. Downstream, Cursor-Governance's projection is pinned at `.github` `496842b` (33 repositories) and `l9-graphiti-memory`'s corpus at `9b27869` (32), so the organization's membership was already held in more than one place and drifting.

Constellation participation is a separate question. It is defined by `Constellation.Gate` and `Gate_SDK` and, in this ledger, by ProductKind `node` (`semantics/product_kinds.yaml`, ADR-011). The registry does not own ProductKind (`does_not_own: product_kind`) and never did.

## Options considered

- **A — Keep curated membership and add the 27 by hand.** Fixes today, drifts again with the next repository, and leaves "is every organization repository registered?" unanswerable. Rejected by decision 2.
- **B — Infer membership from organization hosting (no entry).** Removes the explicit admission decision (`every_entry_is_an_explicit_admission_decision`) and gives the memory view no stable id or class to resolve. Rejected.
- **C — Org-complete registry: hosting creates an obligation to register, the entry still confers membership.** Every hosted repository must have an entry; leaving one out is a violation an observational check reports; each entry is still an explicit, reviewable decision with an explicit class. Adopted.

## Decisions (proposed)

1. **Supersession.** The global rule `organization_hosting_does_not_imply_l9_membership` is superseded and removed. In its place: `organization_hosted_repositories_must_be_registered`, `membership_is_conferred_by_registry_entry_never_by_organization_hosting`, `registry_membership_does_not_imply_product_kind` and `registry_membership_does_not_imply_constellation_participation`, all `true`. `every_entry_is_an_explicit_admission_decision` and `unregistered_repository_has_no_implied_l9_membership` stay: an unregistered hosted repository is a completeness violation, never an implied member. RC-023 pins that the superseded key is absent and its successors present, so the ledger cannot carry both readings.
2. **Membership is organization membership only.** A registry entry does not assign a ProductKind, does not make a repository a Node, and does not make it a constellation participant. Constellation participation stays owned by `Constellation.Gate` and `Gate_SDK`, and ProductKind by `semantics/product_kinds.yaml`. The class catalog is unchanged, including its prohibition `infer_repository_membership_from_organization_hosting`: membership is still conferred by the listing; completeness is an obligation on the listing.
3. **Scope.** Every repository the organization hosts on GitHub, archived and forked ones included. An archived repository is registered with lifecycle `retired` (`removed_repository_entries_must_be_retained_with_retired_lifecycle`).
4. **Admission of the 27.** Each is registered with class `l9.repository-class/l9@1`, no ProductKind, exact case-sensitive coordinate and lifecycle `current`, except `golden-repo`, which GitHub reports archived and is registered `retired`. They join the RC-023 pinned census, which grows from 33 to 60; the registry holds 61 entries with `l9-state`.
5. **Id rule for every entry.** Memory derives namespace addresses from registry ids, so every id is the folding of its repository name — lowercase, every run of `.`, `_` and `-` folded to one `-`, trimmed (ADR-039's rule). `dot-github` is the one grandfathered pre-rule id: `.github` folds to no valid id. RC-023 checks this for every entry. Existing ids are unchanged (`repository_id_is_immutable`).
6. **Organization-admitted entries.** A repository created after v3.43.0 is proposed by `ops/register-org-repository.py`, run by the `admit` job of `auto-seed-new-repo.yml` for a targeted repository. The entry has exactly `id`, `coordinate`, `lifecycle: current`, `class_ref` (the single current admitted class, failing closed if it is not unique) and `organization_admission {basis: organization_completeness, decision_record: ADR-040, github_repository_id, observed_at}`. The marker is evidence of the observation (L9-EVIDENCE-001): it confers no authority and implies no class or ProductKind. RC-023 checks such an entry by shape, as it does a factory-born entry, rather than through a second hand-maintained pin (ADR-039's rejected option C). An entry never carries both `organization_admission` and `birth_provenance`, and a pinned entry carries neither. A repository with a birth receipt is left to the birth path (ADR-039); an already-archived one is refused and admitted by hand with lifecycle `retired`. The job opens a pull request with the entry and its registry-only release record and never merges: the owner's merge is the admission decision.
7. **Completeness check.** `ops/registry-completeness.js` compares the live organization listing with the registry and fails on any hosted repository the registry does not list, and on an archived repository registered `current`. It is observational (L9-VALIDATION-001): it reads, reports and exits non-zero; it never writes the registry and never opens a PR. `registry-completeness.yml` runs it daily, on dispatch, and on every push to `main` that touches the registry. `scripts/validate-semantics.py` stays network-free and deterministic.
8. **Downstream.** The registry is the single list. `l9-graphiti-memory` (lane L2) re-projects `l9.repository-view/memory-namespace-l9@1` into per-repository memory write grants and Cursor-Governance (lane L3) refreshes its projection bundle; neither maintains a list of its own (`downstream_obligations`). This record changes neither the view's semantics nor any memory grant or namespace naming, which the memory plane owns.
9. Nothing else changes: no invariant, contract, term, capability, receipt family, lifecycle value, RepositoryClass, derived view, projection or composition profile, and no existing registry entry.

## Consequences

- Every Quantum-L9 repository resolves through the memory-namespace view once L2 and L3 re-project; agents in the 27 can write to memory under the class's existing obligations.
- A new repository is visible as a completeness failure until it is admitted, and its admission needs no hand-typed entry, pin edit or release record.
- RC-023-NEG grows from 70 to 99 cases.
- **Outstanding Unknowns.** No organization webhook dispatches `repo_created` today, so the `admit` job runs when a birth dispatches it or an operator runs `auto-seed-new-repo.yml` with `target_repo`; until then the scheduled completeness check is the detector. Whether the org secret `GH_TOKEN` can list every private repository and open a PR on `.github` is unverified here, as in ADR-039. The listing on 2026-11-17 was read through the search API and the session's repository listing; both returned the same 61 repositories.
