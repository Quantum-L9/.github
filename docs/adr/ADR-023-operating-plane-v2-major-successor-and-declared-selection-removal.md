# ADR-023 — Operating-Plane @2 as a Declared Major-Version Successor, and PROJECTION-014 Exact Selection Removal

**Status:** Candidate for semantic-foundation v3.26.0. Drafted on 2026-10-22 at the repository owner's instruction to repair the Cursor-Governance operating-plane profile lineage in place. Admission of v3.26.0 is the acceptance gate; this record does not admit itself.

## Context

`l9.projection/cursor-governance-operating-plane@1` (v3.9.0) selects, besides eight `.github`-owned source classes, three `conformance_profiles` coordinates (`$.published_profiles[*].id`, `.digest`, `.status`) whose canonical source is published by `Quantum-L9/l9-conformance`, not by this repository. No admitted producer can project that class from `.github`, so the profile has never been receipted whole, and its consumer bound `l9.projection/coding-agent-execution@1` instead (Cursor-Governance `skills/l9-coding-agent` 1.3.0). The profile also predates the decision-complete selections the later consumer profiles carry: whole contract records with `owner` and `applies_to`, admission and promotion rules, lifecycle state semantics, result domains, and the receipt kernel.

PROJECTION-014 as written admits only a successor that keeps every predecessor selection. A successor that drops the three foreign-owned selectors is therefore inexpressible: the lineage can only be abandoned for an unrelated profile, which forfeits the versioned continuity PROJECTION-013 and the `superseded_profile_versions_remain_valid_for_exact_historical_resolution` rule exist to protect. The compiler enforces the superset rule independently (`l9-semantic-compiler-engine` `passes/projection.py` `_succession_criterion`), so a catalog-only change would be rejected at projection time.

## Decisions

1. **Profile.** `l9.projection/cursor-governance-operating-plane@2` is a `consumer` profile for `Cursor-Governance`, `successor_of` `@1`. It keeps all 32 predecessor selectors in the eight `.github`-owned classes (`vocabulary`, `capabilities`, `authority_model`, `lifecycle`, `invariants`, `contracts`, `error_taxonomy`, `receipt_catalog`) and adds 23: six vocabulary terms (`invariant`, `contract`, `admission`, `provenance`, `resolution`, `requirement`); the capability `global_rules`, `capability_relations`, `catalog_status`, and the whole `capabilities` collection; `admission_rules`, `global_admission_rules`, and `promotion_rules`; the lifecycle `global_rules`, `state_semantics`, and `lifecycle_relations`; the whole `$.contracts[*]` record and `outcome_semantics`; `result_domains`; and the receipt `global_rules`, `receipt_kernel`, `specialization_contract`, and `receipt_relations`. It selects 55 paths in total and declares `output.schema: l9.projection.cursor-governance-operating-plane/v2`. Its `forbidden` list is three of the five ADR-020 categories.

2. **Declared break.** The profile removes exactly the three `conformance_profiles` selectors and declares them in `breaking_changes.removed_selections`, with a `rationale` and `consumer_migration: explicit`. `@1` is unchanged byte for byte and remains resolvable at its exact identity. `l9-conformance` alone publishes conformance-profile evidence; a consumer that needs it resolves it from that owner.

3. **PROJECTION-014.** The rule becomes `successor_profile_keeps_class_and_consumer_and_either_preserves_all_selections_or_declares_exact_major_version_removals_with_explicit_consumer_migration`, and the catalog `global_rules` key `profile_successor_declares_successor_of_and_preserves_every_predecessor_selection` is replaced by `profile_successor_preserves_selections_or_declares_exact_major_break`. A successor that preserves every selection is unchanged in law. A successor that removes any selection must: be a higher decimal version of the same profile family (`<base>@N` with `N` greater than the predecessor's); keep class and consumer; carry `breaking_changes` with exactly the keys `removed_selections`, `rationale`, `consumer_migration`; list every removed `{source_class, selector}` exactly once and nothing else; give a non-empty rationale; and set `consumer_migration: explicit`. `breaking_changes` without `successor_of`, or without any removed selection, is invalid. The compiler realizes the same criterion and receipts `breaking_major: true` with the removed selections, so the receipt records the break rather than hiding it.

4. **Payload schema.** `semantics/cursor_governance_operating_plane_v2_projection.schema.yaml` (`l9.schema/cursor-governance-operating-plane-v2-projection@1`) defines `l9.projection.cursor-governance-operating-plane/v2` through `properties.schema.const`, the only way the compiler resolves a declared output schema to a registered artifact schema. It types every section the 55 selectors can produce and requires the identity fields each canonical source declares; contracts require the whole-record fields `owner` and `applies_to`. No single source carries all sections, so no section is `required`. It is registered under `requires.artifact_schemas`. Every keyword used is one the canonical dialect enforces.

5. **Consumer binding.** Cursor-Governance consumes the profile only through the existing producer driver, the shared consumer verifier, the shared admission resolver, and the trusted replay, under the ADR-021 conventions; it releases a source class or one exact record only when the bundle is admitted and current against independently resolved `main`. The consumer never produces the projection. This record grants no mutation, publication, merge, admission, or execution authority.

## Review findings (recorded, not resolved)

- The owner-side validator pins the other consumer profiles with a release check (RC-028, RC-030, RC-032). No RC-033 for this profile is authored in this candidate; whether admission requires one is the owner's decision.
- The explicit decision record that `authority_model.admission_rules` requires for admitting a projection as law still has no defined form in a ledger (the v3.24.0 finding); the consumer's binding carries it until one exists.
- Both `global_rules` sections selected by `lifecycle` and `receipt_catalog` are typed as bare objects in the projection schema, as ADR-022 recorded for the same situation; selection equivalence proves the per-source key set.

## Consequences

The operating-plane lineage continues under its own identity with a receipted, decision-complete `@2`, and the superseded `@1` stays historically resolvable. PROJECTION-014 now distinguishes an additive successor from a declared major break and refuses every partial or silent removal; any later profile that drops a selection must say so in the same exact form. A change to any selected record or section is a material change under PROJECTION-007 and PROJECTION-008 and re-opens the receipt.
